    Database Primer
        What is:
            "dataset" , "spreadsheet" , "database" , "datalake"
        Database
            A database is a collection of structure information organized for a specific purpose
            Relational Database
                The most prevalent type of database used
                information is organized into related tables
                Each table capture information about a different entity
                Columns are different fields of information (attribute)
                Each row represents one instance
                Goals
                    First step in database design is to identify entities
                    Entities are things that you want to know info about
                    Figure out what we care about for the system
                Normalization
                    Def: A process through which a database design is cleaned up
                    Not all database designs are equal
                    Certain structures and relationships are easier to maintain and process than others
                    1NF: First Normal Form
                        All attributes are single valued
                        All instances have a unique identifier
                        Multi Valued attributes generally indicate the need for a new entity
                        Unique Identifiers
                            What can act as a unique identifier
                            Usually the best way is to create your own id property to differentiate 
                        Modeling Relationships
                            Two types: One to many, many to many
                    2NF: Second Normal Form
                        Non-identifying attributes are dependent on the entity's unique identifier
                        If the same value appears multiple times for an attribute think if what you need is really another entity
                    3NF: Third Normal Form
                        To fix, generally want to pull the dependent
                        attributes out into their own entity
            Logical vs Physical Design
                Result so far is "logical" database design
                Need to implement this design as a specific database
                ie. relational database
                    Implementing 1 to many
                        add an attribute on the many side which is the unique identifier of the one side
                        "put the id on the many side" and the value on the one side
                    Resolving many to many
                        Hard to implement
                        Breaks 1NF structure
                        Junction Entities
                            Create a arbitrary table (cross table, join table)
                            abstract entity provides a level of indirection for a many-to-many relationship
