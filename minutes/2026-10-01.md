## Deploy!?

1. list my instance's IP: 
    ```sh
    gcloud compute instances list
    ```

1. run make migrations after changing models.py (like adding new models, changing/altering tables)
    1. it is safe to run make migrations at any point in time (because it defaults to saying "no changes")

2. make migrations vs migrate
    1. migrate migrates any unapplied migrations to the correct files
    2. django knows we need a migration when it senses that models.py has changed

3. schema migration vs data migration
    1. schema migration: django's way of adding changes to models in database
    2. data migration: a declarative way to write some python code to change entries in the database (CRUD), no change to the structure of the data, just new stuff added to the database

4. db client: lets you change data in django outside of django (tool to connect to django database)

5. backend receives HTTP request, end goal is to respond with a HTTP response/HTML page
